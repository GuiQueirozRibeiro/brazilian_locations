# Architecture — brazilian_locations

## Overview

A cross-platform Flutter **plugin package** with a pure-Dart data layer. The package has no native business logic in platform channels — the native stubs exist only to satisfy the Flutter plugin registration requirement. All real functionality lives in Dart.

```
lib/src/
├── models/          # Hive-annotated data models
├── services/        # IBGE API + cache logic
└── widgets/         # Public UI components
```

---

## Data Flow

```
App startup (optional)
  └─ BrazilianLocations.initialize()
        └─ CacheService.initializeHive()
              ├─ Hive.init(documentsDir)
              └─ Open 'brazilian_locations_box'

Widget build / first interaction
  └─ CacheService.loadData()
        ├─ Cache exists AND age < 7 days → return cached List<Location>
        ├─ Cache stale/missing → fetchAndCacheData()
        │     ├─ GET https://servicodados.ibge.gov.br/api/v1/localidades/distritos
        │     ├─ Parse: item.municipio.microrregiao.mesorregiao.UF.sigla + item.municipio.nome
        │     └─ saveData(locations) → Hive 'cache' key
        └─ API fails + old cache exists → return stale cache (graceful fallback)
```

---

## Key Components

### `CacheService`
Single responsibility: abstract IBGE API + Hive persistence behind `loadData()`. Stateless — all state lives in the Hive box.

- `initializeHive()` — idempotent, safe to call multiple times
- `loadData()` — the single entry point for consumers; handles all caching logic internally
- `fetchAndCacheData()` — network only; sorts results by state UF after parsing
- 15-second HTTP timeout; per-item try/catch prevents one bad record from failing the entire dataset

### `BrazilianLocations` (Stateful Widget)
Orchestrates the two `DropdownWithSearch` widgets. Holds selected state/city in local `State`. Calls `CacheService.loadData()` in `initState` (or deferred on first open if not pre-initialized). Exposes 25+ styling and behavior parameters — none of them affect data loading.

### `DropdownWithSearch` (Stateless Widget)
Generic; receives `items`, `selected`, and `onChanged`. On tap, opens `SearchDialog` via `showDialog`. Returns selected value via callback.

### `SearchDialog`
Stateful. Maintains a filtered copy of `items` driven by a `TextField`. Real-time filtering on every keystroke.

## Models

```dart
@HiveType(typeId: 0)
class Location {
  @HiveField(0) String state; // UF code, e.g. "SP"
  @HiveField(1) String city;  // full city name
}

@HiveType(typeId: 1)
class CacheData {
  @HiveField(0) List<Location> locations;
  @HiveField(1) DateTime timestamp;
}
```

Adapters are generated by `hive_generator` via `build_runner`. Run `dart run build_runner build --delete-conflicting-outputs` after changing model fields.

---

## Platform Channels

All platform implementations (`BrazilianLocationsPlugin.kt`, `.swift`, `.cc`, `.cpp`) expose only a `getPlatformVersion` method. This is boilerplate — the package does not use platform channels for any actual functionality.

The web variant (`lib/brazilian_locations_web.dart`) uses JS interop for `getPlatformVersion` only.
